# ChainTrace 整体学习计划

## 目标与背景

用户有多年 PHP 后端、Python、SQL、ETL 和业务系统开发经验，能独立交付系统。
学习目标是将已有开发能力迁移到区块链技术应用，用技术解决问题获得收入。
此前学习 RAG、Agent 的求职转化不理想，希望避免无边界追热点。
技术学习无需先完成客户开发或付费需求验证；完成项目也不等于已经验证就业或收入。

主线：**Python → EVM 链基础 → 链上数据与应用后端**。
最终项目：**可持续运行、可核验、可恢复的 ERC-20 地址转账监控系统**。
AI 负责大部分代码实现；用户重点掌握概念、机制、数据流、异常处理和正确性核验，而非死记语法或 SDK。

## 六个里程碑

| 里程碑 | 核心问题与学习范围 | 验收成果 |
| --- | --- | --- |
| M1：读懂一笔交易 | 区块、地址、账户、节点、RPC、交易与回执；Gas、Nonce、签名的基本含义 | Python 查询链 ID、区块高度、公开地址原生币余额、一笔交易及回执；与区块浏览器核对，解释金额、手续费、状态，以及广播成功不等于执行成功 |
| M2：读懂一种代币 | EVM、合约、ABI、ERC-20；balanceOf、decimals、transfer、approve、allowance；整数精度和资产身份 | 查询代币信息与地址余额，解释原生币与代币、授权与转账的区别；金额不使用浮点数 |
| M3：可靠采集历史转账 | 日志、Transfer、ABI 解码、区块范围查询、入库、幂等、限流、重试 | 指定代币和区块范围采集转账；抽样核对正确，重复运行不重复入库，失败可重试 |
| M4：理解交易写入全过程 | 本地开发链或测试网专用账户；构造、签名、广播、Nonce、Gas、回执、超时与失败 | 完成测试转账；区分请求失败、广播结果不明确、待确认、执行成功与失败，理解超时不代表未广播 |
| M5：持续运行与恢复 | 地址与代币配置、检查点、补数、确认策略、区块重组、日志告警 | 持续监控指定地址 ERC-20 转账；用重启、超时、限流、区块变化实验核验无漏数、无重复、无错误推进进度 |
| M6：整理交付 | 启动说明、配置、表结构、核验说明、演示；简单 API 与页面 | 别人能按说明运行；能演示监控和恢复，讲清数据来源、确认条件、能力与当前限制 |

M3 是第一个完整成果；M5 是核心项目完成点；M6 是交付完成点。
M3 至少保存：链 ID、合约地址、区块高度与哈希、交易哈希、日志序号、发送方、接收方、原始金额、区块时间。
初期只采集 ERC-20 转账事件；原生币转账和内部调用追踪以后再扩展。

## 时间预算

按每周 4～6 小时，参考安排：第 1 周 M1，第 2 周 M2，第 3～4 周 M3，第 5 周 M4，第 6～7 周 M5，第 8 周 M6。
时间只是预算，按验收结果推进，不因周数到了就跳过问题。

## 固定教学循环

每次开始说明：

- **当前位置**：里程碑与步骤。
- **本次问题**：这次只解决什么。
- **完成证据**：得到什么结果，如何核验。

步骤：**解释概念与数据流 → 用户预测结果 → AI 实现最小实验 → 核对结果 → 制造异常 → 查看关键代码**。
每个里程碑需要三类成果：可运行代码、核验记录、用户自己的简短解释。
金额换算、状态变化、幂等与补数、签名与权限相关逻辑必须单独解释。

## M1 的具体安排

### M1-0：准备环境

使用 uv 管理 Python，固定版本；建立项目虚拟环境、Git 忽略规则和跨电脑使用说明。
环境验收：`uv sync --locked` 成功，`uv run --locked chaintrace` 输出 Python 与虚拟环境信息。
环境完成只代表可以运行 Python，不代表已连通 RPC。

### M1-1：理解读取路径，查询链 ID 与区块高度

先解释：本地 Python 程序 → 远程 RPC 节点 → 节点返回链上数据。
节点提供查询接口，程序无需自建节点或下载整条链；区块浏览器用于核验。
让用户先预测查询是否需要钱包、私钥或支付 Gas，再实现最小查询。
选择以太坊网络及 RPC 服务，说明如何配置本地 `.env`，提交不含密钥的 `.env.example`。
按需加入查询所需依赖，不提前增加数据库或监控功能。
验收：输出链 ID 与最新区块高度；确认网络正确，理解浏览器与 RPC 查询时间不同可能造成高度差。

### M1-2：查询公开地址的原生币余额

解释地址、余额原始整数和 wei / ETH 单位关系，先预测再查询。
验收：记录地址与查询区块，核对同一网络、尽量相同区块的数据；解释单位换算，避免浮点误差。

### M1-3：查询一笔交易及回执

使用公开、已完成的简单 ETH 转账，解释交易请求与执行回执的区别。
验收：核对发送方、接收方、金额、区块、执行状态；依据回执的实际 gasUsed 和 effectiveGasPrice 解释执行手续费。

### M1-4：观察异常并完成验收

尝试错误 RPC 地址、不合法的地址、不存在的交易哈希。
区分连接失败、参数错误、查无结果；说明未查到不等于交易执行失败。
留下核验记录和用户自己的解释；尚未理解的概念继续补齐。

M1 全程只读公开数据，不需要私钥、签名、转账、数据库或自建节点。
实际脚本路径随实现决定，以上是学习步骤，不表示代码已经存在。

## 范围边界

暂缓 Go、Rust、多链、深入 Solidity、DeFi 策略、套利、MEV、自建节点、复杂索引平台、微服务、Agent 集成、复杂前端与商业化验证。
只有新知识直接阻碍当前里程碑验收时才补学。

## 跨电脑环境

公司 Windows 使用 WSL Ubuntu，家中 Mac 使用本机终端；两边均用 uv，当前不使用 Docker。
代码、计划、学习记录、依赖与版本配置通过 Git 同步；虚拟环境在每台电脑分别重建。
链上公开数据可重新查询；私钥、RPC 密钥和运行数据不进 Git。
具体命令见 README，最新进度见 `docs/progress.md`。
