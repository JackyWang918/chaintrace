## M1-1 实验记录（2026-10-15）

- 概念路径：本地 Python → 远程 RPC 节点 → 返回链上数据；浏览器用于交叉核验。

- 用户自己的解释：“Python 通过 RPC 接口向远程节点查询，节点返回它掌握的链上数据。私钥用于签名，证明你有权发起某些操作，例如花费某个账户里的 ETH。然而这里是查询公共的数据，而不是操作数据，所以不需要私钥。”读取路径与本次查询无需私钥的原因解释正确。教学补充：此处“操作数据”可更准确地说成“发起改变链上状态的交易”；节点会验证签名，实际执行还受余额等规则约束。

## M1-2 实验记录（2026-10-15）

- 用户预测：`1500000000000000000 wei` 为 `1.5 ETH`，回答正确。
- 最小实现：`uv run --locked chaintrace balance 0x000000000000000000000000000000000000dEaD`。程序先验证地址格式和主网链 ID，再取得区块高度，并以该高度作为 `eth_getBalance` 的区块参数。
- 金额换算：`1 ETH = 10^18 wei`；用整数 `divmod` 拆分整数部分和 18 位小数部分，未用浮点数。`1.5 ETH` 与 `1 wei` 的换算样例运行通过。
- AI 在 WSL 实测：2026-10-15 09:29:46 UTC（北京时间 17:29:46），链 ID `1`，公开示例地址 `0x000000000000000000000000000000000000dEaD`，区块 `26197023`，余额 `12640664688726093233101 wei` = `12640.664688726093233101 ETH`。
- 用户亲自运行证据：2026-10-15 09:34:46 UTC（北京时间 17:34:46），链 ID `1`，相同公开地址，区块 `26197048`，余额 `12640664688726093233101 wei` = `12640.664688726093233101 ETH`。区块高度增加 25，两个查询点的余额相同；这不证明中间每个区块的余额都相同。
- 浏览器辅助核对：https://etherscan.io/address/0x000000000000000000000000000000000000dEaD 。工具请求收到 403；用户随后提供页面 ETH Balance 为 `12,640.664688726093233101 ETH`，去掉千位分隔逗号后与程序输出完全一致。核验依据为用户提供的页面内容；页面对应区块未明确，不能声称两者为同一区块查询。
- 异常：用户亲自执行 `uv run --locked chaintrace balance bad-address`，收到“查询失败：地址格式错误：应为 0x 开头、后接 40 位十六进制字符”。代码在发出 RPC 前检查地址，参数无效不等于余额为零。
- 已展示关键代码：`divmod(wei, 10**18)` 拆分 ETH 整数与小数部分；`eth_getBalance` 使用前一步取得的 `block_raw`，查询指定区块的余额。金额换算未使用浮点数。
- 用户自己的解释：原始余额单位为“wei”，换算 ETH 为“除以 10¹⁸ wei”；区块号用于描述“这段时间，这批交易账户的当时情况”。单位与换算正确，区块定位理解基本正确；已补充：在已确认网络的前提下，区块号定位该区块执行完成后的链上状态，地址无需在该区块发生交易；余额是该地址在此状态下的余额，而非一段时间或仅该批交易所涉账户的信息。
- M1-2 验收：可运行代码、用户实际查询、浏览器显示金额核验、无效地址实验、关键代码展示和用户简短解释均已有证据，本步骤完成。浏览器页面未明确对应区块，因此仅记录显示金额一致，不声称同区块独立核验。
